# Companion Event Protocol v1 (Open Agent Companion 1.0.0)

The protocol is local, append-only JSONL. Agents publish events to a
companion's `inbox.jsonl`; the runtime publishes acknowledgements to
`outbox.jsonl`.

Protocol version `companion-event-v1` is frozen for 1.x. New fields are
optional and ignored by older readers; new event types require a minor
version bump and a SPEC entry.

## Event envelope

Required fields are `version`, `id`, `agent`, `created_at`, and `type`.
`version` is `companion-event-v1`. IDs are unique strings generated by the
publisher. Timestamps are ISO-8601 UTC strings.

Supported event types are `summon`, `hide`, `say`, `state`, `mood`, `move`, and
`status`.

`say` requires a non-empty `text` field and accepts an optional non-negative
numeric `ttl` in seconds and integer `priority` (default `0`). Higher priority
messages are displayed first. `state` and `mood` use one of `idle`, `thinking`,
`working`, `success`, `error`, `waiting`, or `hidden`. `move` uses one of
`top-left`, `top-right`, `bottom-left`, `bottom-right`, `dock`, or `free`.

Example:

```json
{"version":"companion-event-v1","id":"evt-001","agent":"terra","created_at":"2026-09-09T12:00:00Z","type":"say","text":"Milestone 1 terminado","ttl":8}
```

## Delivery

The runtime processes complete lines in file order. A final line without a
newline is left unread until the writer finishes it. Invalid complete lines
produce an `error` report and do not stop the runtime.

For accepted events the runtime emits:

```json
{"version":"companion-event-v1","status":"accepted","event_id":"evt-001","event_type":"say"}
```

The MVP lease fields are optional metadata. A lease groups events from one
agent and is not an authorization or security boundary. Future versions may
add `lease_id`, retry policy, and explicit `displayed` or `expired` reports.

## Local scheduled events

Reminders are persisted separately in `reminders.json` as a JSON array of
`ScheduledEvent` records:

```json
{
  "id": "rem_001",
  "due_at": "2026-09-09T19:30:00-06:00",
  "message": "Sacar la ropa",
  "companion_id": null,
  "mood": null,
  "ttl": 8,
  "created_at": "2026-09-09T18:00:00-06:00",
  "status": "pending"
}
```

Statuses are `pending`, `fired`, `cancelled`, and `snoozed`. The scheduler owns time and
the runtime owns display. A pending record fires when `now >= due_at`, never by
exact equality. It is marked `fired` before output events are appended, which
prevents duplicate firing on the next poll or after restart. An overdue
pending record fires once on startup. A cancelled record never emits.
A snoozed record waits until `snoozed_until` before becoming `pending` again.

Optional recurrence keeps the same pipeline. `recurrence` is `daily`,
`weekly`, or `countdown` with optional `weekdays` (`mon..sun`). A recurring
record emits once and reschedules instead of becoming `fired`: `daily` is
+1 day, `weekly` without `weekdays` is +7 days (with `weekdays`, the next
matching weekday), and `countdown` decrements integer `message` as `N..1`
each minute until the final tick fires. Timers (`--in 30s/10m/2h/1d`) and
pomodoro plans are producers only: they create one-shot records through
`create`, never a runtime feature.

For each due reminder, the scheduler appends a normal `say` event to the
existing inbox. An optional canonical `mood` event may follow. Reminder text
is data only and is never interpreted as a shell command or executable action.

System notifications are an optional presentation adapter only
(`adapters/notify.py`). They are best-effort, local, and never block
acceptance into the inbox.

## Asset packs

An asset pack is a directory with a `manifest.json`. The manifest maps generic
states to relative GIF/PNG files. The loader rejects unknown states, missing
files, malformed manifests, and paths that escape the pack directory. Rendering
selects `mood`, then `state`, then `idle`; the pack decides how those semantic
states look.

When no usable image is available, the desktop window displays the companion
name and current semantic state as text instead of failing silently.
